## Требования

- [Docker](https://docs.docker.com/get-docker/) с Docker Compose (входит в
  Docker Desktop для Windows/macOS; в Linux — пакет `docker-compose-plugin`).
- Больше ничего не нужно: Go-зависимости лежат в `vendor/`, образы стянутся
  сами при первом запуске.

## Запуск одной командой (из чистого клона)

```bash
git clone <адрес-репозитория> && cd cup-trivium
docker compose up --build -d
```

Поднимаются два контейнера:

| Контейнер | Описание |
|---|---|
| `otklik-db` | PostgreSQL 16 (user `otklik`, пароль `default_password`, БД `otklik`) |
| `otklik-app` | Приложение: **8080** — для заявителей, **8081** — для сотрудников |

При старте автоматически применяются миграции (`internal/db/migrations`)
и создаются seed-данные (категории + демо-пользователи) — только если БД пуста.

### Проверка

```bash
curl http://localhost:8080/api/health
```

Откройте в браузере:

- **http://localhost:8080/** — вкладка «Заявитель»: создание обращения,
  вход по трек-номеру, чат с автообновлением;
- **http://localhost:8081/** — вкладка «Сотрудник»: вход под демо-учёткой.

### Остановка и сброс

```bash
docker compose down      # остановить (данные в volume сохранятся)
docker compose down -v   # остановить и удалить все данные (полный сброс)
```

> **Важно:** пароль PostgreSQL считывается только при **первой**
> инициализации volume. Если меняли `POSTGRES_PASSWORD` в
> `docker-compose.yml` — выполните `docker compose down -v` перед новым
> запуском, иначе приложение не сможет подключиться к БД.

## Тестовый веб-интерфейс

Встроенный одностраничный UI (без внешних зависимостей, вшит в бинарь
через `go:embed`), доступен и на 8080, и на 8081:

- вкладка **Заявитель** — создание обращения (категория или свободный текст,
  ответы анкеты), вход по трек-номеру, чат с автообновлением, результат
  («помогло/не помогло»), оценка, жалоба; трек-номера сохраняются в localStorage;
- вкладка **Сотрудник** — очередь оператора (назначение эксперта, приоритет,
  категория, отклонение, завершение; обращения с запросом передачи помечены
  бейджем «↔ требуется другой специалист»), рабочий процесс эксперта
  (`take → clarify → recommendation → transfer-request → close-no-response`),
  чат и заметки с автообновлением, аудит, админ-панель (пользователи,
  категории, жалобы, метаданные обращений).

## Модель приватности

Приложение построено вокруг анонимности заявителя и принципа минимальной
необходимости данных для каждой роли:

- **Никакой регистрации.** Заявитель не оставляет имя, e-mail или телефон:
  обращение создаётся анонимно, доступ — только по трек-номеру.
- **Физическое разделение контекстов.** Публичная часть (заявители) и служебная
  часть (сотрудники) слушают на **разных портах** — 8080 и 8081. Маршруты
  сотрудников на публичном порту недоступны в принципе (и наоборот): это
  уменьшает поверхность атаки и упрощает сетевые ограничения (например, служебный
  порт можно закрыть от интернета на файрволе).
- **Секреты хранятся только хешами.** Трек-номера и токены сессий (сотрудников
  и заявителей) лежат в БД как SHA-256 — утечка базы не даёт доступ к
  обращениям. Пароли сотрудников — bcrypt.
- **Проекции по ролям:** заявитель видит минимум (без имён, внутренних заметок
  и аудита); эксперт — только назначенные ему обращения; оператор — рабочие
  данные очереди; админ — только метаданные обращений.
- **Вложения обезличены:** исходные имена файлов отбрасываются (выдаются как
  `attachment.bin`), тип проверяется по фактическому содержимому
  (whitelist MIME), отдача — с `X-Content-Type-Options: nosniff`; лимит —
  5 файлов по 10 МБ.
- **Rate limits:** создание обращений — 5/час с одного IP; попытки входа по
  трек-номеру — 20/час с IP (защита от перебора); логин сотрудников —
  10/минут с IP.
- **Сессии ограничены по времени:** TTL 2 часа (`SESSION_TTL_MIN`).

## Принятые проектные решения

### Трек-номер

Трек-номер — единственный способ доступа заявителя к обращению
(bearer credential: предъявивший верный секрет считается владельцем),
поэтому к нему особые требования:

- Формат `ОТК-X7KD-R9MF-Q3HP`: 12 значащих символов из алфавита без похожих
  символов (`0/1/I/L/O` исключены), генерация криптостойким `crypto/rand`
  — перебор на практике невозможен и дополнительно блокируется rate limit.
- Выдаётся **ровно один раз** при создании обращения и **не восстанавливается**:
  восстановление означало бы возможность идентификации заявителя (хранение
  копии номера у системы). Потерял номер — обращение недоступно, это цена
  анонимности, принято сознательно.
- В БД хранится только SHA-256-хеш нормализованного номера: оператор и БД
  не знают сам номер. Ввод регистронезависим (`ОТК-…` = `otk-…`).

## Основные эндпоинты

**Публичные:**
- `GET  /api/health` — работает
- `GET  /api/categories` — активные категории
- `GET  /api/intake-questions` — вопросы анкеты
- `GET  /api/help/crisis` — контакты экстренной помощи
- `POST /api/appeals` — создать обращение → трек-номер (выдаётся один раз!)
- `POST /api/appeals/track` — вход по трек-номеру → сессия заявителя (кука)

**Заявитель** (`/api/appeals/me/...`):
- `GET` — статус, объяснение, рекомендации, чат, история, вложения
- `GET|POST /messages` — чат со специалистом
- `POST /result` — «помогло / не помогло»
- `POST /feedback` — оценка и комментарий
- `POST /complaint` — жалоба на специалиста
- `POST|GET /attachments` — вложения (до 5 файлов по 10 МБ)

**Сотрудники** (`POST /api/auth/login` → кука сессии):
- `GET /api/operator/queue` — очередь оператора
- `GET /api/operator/appeals?status=` — все обращения оператора
- `GET /api/expert/appeals?status=&category=&priority=` — список эксперта
- `GET /api/admin/appeals|users|categories|complaints` — метаданные для админа
- `GET  /api/appeals/{id}` — карточка обращения (эксперт — только свой)
- `POST /api/appeals/{id}/assign|reject|complete|priority|category` — оператор
- `POST /api/appeals/{id}/take|clarify|recommendation|transfer-request|close-no-response|contributors` — эксперт
- `GET|POST /api/appeals/{id}/messages|notes` — чат и внутренние заметки
- `GET  /api/appeals/{id}/events` — аудит (оператор/админ)

## Архитектура

```
cmd/server        точка входа
internal/config   конфигурация из окружения
internal/db       подключение, миграции (go:embed), seed
internal/domain   домен: статусы, трек-номера, кризис-эвристика
internal/store    все SQL-запросы
internal/httpapi  REST API: маршруты, аутентификация, проекции
```

Безопасность: трек-номера и сессионные токены хранятся только в виде
SHA-256 хешей;
